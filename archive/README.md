## roulette チェックポイント（2026-09-06）

ルーレットが一通り仕上がった時点のまるごとの写し。
git タグ `roulette-checkpoint` と同じ中身。

| | |
|---|---|
| `roulette-2d/` | 2D。(角度, 半径) で解く。離脱条件は `ω² = (g/r)·tanα`（Small & Tse, Chaos 2012） |
| `roulette3d/` | 3D の質点＋接触。透視投影、自前レンダラ |
| `roulette-top/` | 物理は 3D のまま、絵だけ斜投影の 2D に落とす（仰角 68°） |
| `roulette-dot/` | 俯瞰版をドット風に（仰角 56°・横 300 ドット・44 色）。玉 1〜6 個 |
| `wheel/` | 区画の数・中身・色を差し替えられる版。賭けなし |

それぞれの README に、どう解いているか・何を測ったか・どこで間違えたかが入っている。

この時点で分かっていた大事なことは 2 つ。

1. **描画と物理に位置を別々に計算させない。** 同じ間違いを 4 回した
   （ゲームの盤、2D 版の 9 区画ずれ、俯瞰版の y 反転、同じ区画の玉の並べ方）。
   位置を決めるのは `pocketStart / pocketAt / pocketCentre` と `restPositions` だけ。
2. **「合っている」ことを確かめるより、「ありえない値が出ていないか」を測るほうが早い。**
   フレットの位相ずれは、出目が一貫していたせいで検算を全部通っていた。
   玉が止まった位置から仕切りまでの距離を測って、幾何的にありえない値が
   出たことで初めて見つかった。

`build.sh` は archive/ を対象にしていない。ここの `index.html` は
凍結した時点のものがそのまま入っている。
