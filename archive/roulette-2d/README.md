# Roulette Européenne

ローグライク（`prototype/`）とは**一切共有していない**単体のカジノルーレット。
参考資料として読めるように、寸法・配列・物理・配当をすべて実物に合わせてある。

- `app.html` — 本体（`<title>` + `<style>` + markup + `<script>` の断片）
- `head.html` — 単体で開くための head
- `index.html` — 上ふたつを `build.sh` が包んだもの。これを開く

## 出目は乱数ではない

乱数は**投げ方だけ**（玉の初速・トラック上の減速・ロータの角速度と向き）。
そこから先は運動方程式が決めている。だから「Tight launch」に切り替えて
初期条件を固定すると、出目は盤の一部に固まる。
偏らないのは盤のおかげではなく、ディーラーの手のばらつきのおかげ。

## 検算

`step()` は画面と統計で同じものを、同じ刻み（DT = 1/480 s）で使っている。
統計だけ粗い刻みで回すと、見ている挙動と数字が別物になるため。

- 20 万回：χ² = 22〜40 / 自由度 36（95% 上限 50.998）、収まらない玉 0
- 平均 10.8 秒・トラック 21 周（実機は 9〜14 秒・15〜25 周）
- 機械投擲：χ² が 5 桁に跳ね、連続 9 区画に 65〜68% が集中（一様なら 24.3%）
- 実プレイ 60 回で、残高が独立計算と完全一致

## 直したバグ（重要）

**玉が乗っている区画と、発表される数字が 9〜10 区画ずれていた。**

`paintRotor` は区画 i を `i*slot − π/2` から描く（0 を真上に置くため）のに、
`step()` は `floor((tb − tr)/slot)` と、π/2 を足さずに区画を数えていた。
描画と物理が区画 0 の位置について別々の約束を持っていた。

`pocketStart` / `pocketAt` / `pocketCentre` の 3 つに集約し、描画も物理も
必ずここを通すようにした。フレット衝突の位相も同じ式に揃えてある。

検査も足りていなかった。物理に「答えは何か」を聞く検査しか無く、
**絵に「何が描いてあるか」を聞く検査が無かった**ので、2000 回全部ずれていても
すべて緑だった。いまは canvas の画素を直接読んで、玉の下の区画の色と
発表された数字の色が一致することを確かめている（`pixel.js`）。

あわせて、決着後に玉が消えてロータが別の角度へ飛んでいたのも直した。
実物と同じく、玉はポケットに乗ったままロータと一緒に回り続ける。
