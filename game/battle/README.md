# battle — 戦闘画面（案F「手札」）／簡易プレイ

## 遊べるところ（簡易）

**盤は実際に回る。**`wheel/` の物理と絵をそのまま持ってきてある。

1. 玉の数（1〜3）を選んで**レバーを引く**（クリック、または Space / Enter）
2. **盤が真ん中で ×2 に拡大**して、玉が転がる
3. 収まった区画の札が、そのまま**手札**になる
4. 盤が戻り、札が**出た順に 1 枚ずつ**効く
5. 敵が頭の上の印のとおりに動く
6. 全部倒すと次の階へ。倒れると地下 1 階からやり直し

### 札 3 枚（絵は送ってもらったもの）

| | 効果 | 区画 |
|---|---|---|
| 錆びたボロ剣 | 最前の敵に 5 ダメージ | 5 / 12 |
| 錆びたクナイ | 全ての敵に 3 ダメージ | 4 / 12 |
| 錆びたハンマー | 最前の敵のシールドを破る／最前の敵に 8 ダメージ | 3 / 12 |

**確率は区画の数で決める。**「この札を出やすくする」＝「区画を増やす」。
同じ札が隣り合わないように配ってある（機械投擲は初期条件が近いので、
固めると隣どうしに固まって出る）。

杖（引いた順が呪文になる）の要素は無い。札は 1 枚ずつ独立して効く。

### 拡大の作り方

倍率は**整数だけ**（×2）。1.5 倍などにすると画素が 2px と 3px に割れる。
盤の裏画面は 168×140 で、canvas の画素数＝仮想ドット数にしてあるので、
×2 にしても格子は割れない。

枠は canvas と**同じ入れ物**に入れてある。別々に置くと、拡大したときに
枠だけ元の大きさで残る。

### 画面を 3 層に分けた

| | |
|---|---|
| `#bg` | 動かないもの（壁・床・筐体）。1 回だけ組む |
| `#whl` | 盤の枠と canvas。**ここだけは組み直さない** |
| `#fg` | 変わるもの（人物・手札・操作・HUD）。手番ごとに組み直す |

ぜんぶ 1 つの文字列で組み直すと、canvas が毎回作り直されて盤が消える。

### 名前がぶつかった 2 か所

盤の物理を持ってきたときに、同じ名前が別の意味で使われていた。

- `S` … ドット絵の色の指定 `S(ramp, step)` ／ 盤の縮尺。盤側を `SCL` にした
- `G` … 重力加速度 9.81 ／ ゲームの状態。ゲーム側を `GS` にした

どちらも `Identifier has already been declared` で即死したので気づけた。
黙って上書きされる名前だったら見つけられなかった。

### 傾けた札はやめた

一度は角度ごとに絵を焼いて扇に開いていたが、**札に名前と効果を載せた時点で成り立たなくなった**。

- 文字を絵に焼き込むと 8 ドットに潰れて読めない（DotGothic16 は 16px 設計）
- だから文字は札の上に HTML で重ねる
- 重ねる以上、札は立てておくしかない（傾けると文字まで傾く）

代わりに真ん中を少し持ち上げた弧にして、「持っている」形だけ残した。

## 見つけた大きな間違い 2 つ

### 1. ディザが 1 つも効いていなかった

`dither()` が返す値は `url("data:image/svg+xml;...")` だった。
これは `style="..."` の中に入る。**`url("` のところで style 属性が閉じてしまい、
`background-image` が丸ごと消えていた。**

エラーは何も出ない。壁の階調・床の階調・機械の明かり・筐体の肌——
**ディザで作ると README に書いたものが、ぜんぶ 1 つも描かれていなかった。**
松明の光が出ないので調べて、初めて気づいた。

引用符をシングルにして直した（`encodeURIComponent` は `'` を encode しないが、
この SVG の中に `'` は無い。属性は全部ダブル＝`%22` になる）。

直した直後は**全部が濃すぎた**。見えないまま数字を決めていたので当然で、
壁・床・筐体・光の密度を全部付け直した。
検算（`bshot.js`）に「ディザが本当に効いているか」を足した。

### 2. 人物の足元が FOOT より下にずれていた

`actor()` が枠に `SHAPES[sp].w/h`（**倍率を掛ける前**の大きさ）を使っていた。
絵は倍率を掛けた大きさで描かれるので、枠から右下へはみ出す。
倍率 1.5 で 12 ドット、2 で 24 ドット下にずれていた。HP の帯が体に重なる。

`spriteW / spriteH` から取るように直した。
**描画と配置に位置を別々に計算させない。**同じ間違いを何度もしている。

## いちばん大事な決めごと（案B から変わらない）

**画面ぜんぶを仮想 640×360 のドットで組んで、最後に整数倍で拡大する。**

盤の裏画面が 300×250 なので、仮想画面ではそれが等倍で置ける。
こうすると盤のドット・人物のドット・枠線・文字が**ぜんぶ同じ大きさの升目に乗る**。

## 札の規格

| | 寸法 | 使う所 |
|---|---|---|
| 大 | 220×308 | 読ませる所（デッキ・図鑑・買い物） |
| 中 | 110×154 | 盤面に持つ手札 |
| 小 | 45×63 | 一覧・持ち物 |

比はどれも 7:5（縦長）。場面が変わっても変わらない。

**大は中のちょうど 2 倍。**絵を 220×308 で 1 枚描けば、中は 2 で割るだけで格子が壊れない。
枠は大きさごとに描き直す（縮小すると細部が潰れて、ただの汚い模様になる）。
ルーン帯と費用の丸は「大」だけ。

### 絵を差し替えるとき

`cardEl(x, y, t, d)` に 3 通りで渡せる。

| | 中 | 大 |
|---|---|---|
| 札まるごとの絵（いま使っているのはこれ） | 110×154 | 220×308 |
| 名前の帯（絵の中にある。ここに文字を重ねる） | x 6..102, y 11..21 | ×2 |
| `d.art` / `d.glyph` | コードで起こす仮の中身 | 同左 |

**この寸法ちょうどか、その整数倍**で描いて渡すこと。
半端な大きさを縮めると、せっかく揃えた格子が壊れる。

## 素人くさく見える原因として潰したもの

### 格子

| | |
|---|---|
| 格子の混在 | 仮想 640×360 の 1 つの升目に統一 |
| 半端な拡大 | **整数倍だけ**。1.5 倍だとドットが 2px と 3px に割れる。余りは中央に置いて余白にする |
| 小数の座標 | 全部整数 |
| 文字が升目に乗らない | ドット書体を**設計サイズの整数倍**でしか使わない（DotGothic16 は 16px 設計 → 仮想 8 ドット） |
| 札の枠を縮小して使い回す | 大きさごとに描き直す。大は中の 2 倍にして、絵は 1 枚で済むようにした |

### にじみ

| | |
|---|---|
| 角丸・ぼかし影・なめらかな階調 | 全部やめて**順序ディザ（4×4 ベイヤー）**で段を作る |
| 斜め線のアンチエイリアス | 回転で作らず**1 ドットずつ階段で刻む**（ガラスの映り込み） |
| 半透明の重ね | 中間色が無限に増えるので、ディザで代用 |

### 色と光

| | |
|---|---|
| 要素ごとに色を選ぶ | 色相ごとの**段（ramp）**で持ち、段からしか選ばない |
| 影がただのグレー | 影は環境の寒色、光は光源の暖色に寄せる |
| 光の向きがばらばら | 全部の凹凸を**左上から**に統一。上と左が 1 ドット明るく、下と右が 1 ドット暗い |
| 奥も手前も同じコントラスト | 奥（上）の石積みはコントラストを落とす |

### ドット絵

| | |
|---|---|
| 平坦な塗り | 形を置いたあと**機械的に陰影を付ける**（空いている側が上か左なら 1 段明るく、下か右なら 1 段暗く） |
| 輪郭が無い／純黒 | **その色相のいちばん暗い段**で縁取る |
| 接地が曖昧 | 人物に硬い接地影、筐体に硬い落ち影。ぼかさない |
| 小さすぎる | 形の座標ごと 1.5 倍にしてから升目に起こす（SVG を引き伸ばすと格子が壊れる） |

### 「貼り付けた感」

| | |
|---|---|
| 盤が「世界に置かれた箱」 | **画面の下半分そのものを筐体の面**にした。盤はその面に開いた窓 |
| 因果の線が無い | 札は筐体の**出口から溝を滑って**並ぶ。溝が 1 本つながっている |
| 取り付けが無い | ガラスの奥に沈め、四隅を**ボルト**で留める |
| 上下が同じ材質 | 世界＝石と木、筐体＝鉄と真鍮。同じ木で作ると床と筐体がつながって段の境が消える |
| 段の境がただの線 | 筐体が床に硬い影を落とす。影が無いと、下段が奥の壁か手前の物か決まらない |
| 操作が世界から浮く | 丸いボタンをやめ、筐体に生えた**縦レバー**にした。右下（親指の来る所）に置く |
| 床が壁の続きに見える | 境に明線を引かず、暗い線 1 本＋ディザで受ける。明線を引くと人物が「棚に乗って」見える |

## 修飾と並び順は廃止した

出た札は**1 枚ずつ独立して効く**。次の札に乗る「修飾」札は無い。
解決の順は**盤で出た順**（玉が収まった順）にしてある。

## 検算

`bshot.js`（枠外に出ていないか・例外）と `bfit.js`（拡大が整数倍か・横あふれ）。

- 640×360 の外に出ている要素なし
- 例外なし
- **ディザが本当に効いている**（12 か所。0 になっていたら上の 1 が再発している）
- 幅 1400 → ×2、1100 → ×1、820 → ×1、430 → 端数（640 より狭いときだけ許す）

### 枠外の検算で 1 回間違えた

`getBoundingClientRect` を素で見ていたので、**ガラスの中の映り込み**（`overflow:hidden`
で切られている斜めの帯）が毎回「枠外」に出ていた。
親の切り取りを掛けてから測るように直した。

ただし **`#scr` 自身の切り取りは掛けてはいけない**。掛けると、本当に画面の下に
はみ出した「投げる」の銘板（`y 365`）まで見逃す。実際に一度見逃した。
切り取りを見てよいのは `#scr` の内側の親だけ。

## まだ無いもの

- 札は 3 枚だけ。デッキを組む・買う・捨てるは無い
- 敵は 3 体固定。階が上がっても同じ 3 体が出てくる
- 音は無い。演出も最低限（当たった時の点滅なども無い）
- 数字（HP・ダメージ・階数）は仮。バランスは取っていない
