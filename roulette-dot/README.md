# Roulette — ドット

**物理は 3D 版・俯瞰版とまったく同じ。**絵の落とし方も俯瞰版と同じ斜投影。**仰角は 56° 固定**（俯瞰版は 68°）。
違うのは仕上げの 2 手だけ。

## ドットにする 2 手

| | |
|---|---|
| ① 低解像度に描く | 横 **300 ドット**の裏画面に描いてから、`imageSmoothingEnabled = false` で引き伸ばす。画素が四角いまま拡大される |
| ② 色を丸める | 引き伸ばす前に、この画面のために選んだ **44 色**へ丸める。階調が段になる |

色の丸めは、毎フレーム全画素で最近色を探すと重い。
`32×32×32` の引き当て表を起動時に一度だけ作り、以降は

```js
LUT[(r>>3)<<10 | (g>>3)<<5 | (b>>3)]
```

の 1 回で引く。距離は人の目に合わせて緑に重みを置いた（0.30 / 0.59 / 0.11）。
1 フレーム **2.8 ms**。

## 数字だけドットにしない

300 ドットの幅だと 1 区画は 20 ドットほどしかなく、2 桁の数字をドットで
焼くと読めない。数字は**丸めた後に等倍で**書いている。
盤はドット、文字は普通、という混ぜ方。

色はゲーム本体（`prototype/`）とは無関係に、この画面のためだけに選んだ。

## 玉を複数投げる

玉は **1〜6 個**まで同時に投げられる。**玉 1 個が 1 回ぶんの勝負**で、
賭け金も玉の数だけかかる。賭け 100 × 玉 3 なら 300 出て、3 つの出目それぞれで清算される。
控除率は玉を増やしても変わらない（どの玉も 1/37）。増えるのは 1 回あたりの分散だけ。

| | |
|---|---|
| 投げ方 | 初速を **±3.5%/玉**ずらし、投入位置を円周に等間隔で配る。同時に同じ点から投げるとずっと団子のまま走る |
| 玉どうしの衝突 | 中心間距離が直径を切ったら、法線方向の相対速度だけを反発係数 0.55 で交換する。**近づいていない（相対速度 > −0.02 m/s）ペアは弾かない** |
| 収まったあと | 玉は**止まったその場所のまま**ロータに固定して、一緒に回るだけ。ポケットの中心へ寄せ直さない（寄せると決まった瞬間に数センチ跳ぶ）。覚えるのはロータに対する角度差・半径・高さの 3 つで、区画を決めたときと同じ角度差なので、描く場所は必ず発表と同じ区画に入る |
| 落ち着かせ方 | ポケット帯の底を外へ **3 mm** 落とした。平らだと玉が帯の内側の角に集まり、後から来た玉が円錐の上で詰む。さらにポケットに入った玉は速度をゆっくり抜き、**18 秒**を超えたらその場の区画に落とす |

つまずいた順に、原因は 4 つあった。

1. 1 玉時代の書き残し（`s.spin[2]`）
2. ポケット内の減衰タイマを、隣の玉に小突かれるたび 0 に戻していた → 累積にした
3. 衝突処理が、押し合って動かない玉の停止判定を毎フレーム潰していた → 近づいていないペアを弾かない
4. ポケットの底が平らで、内側の角に玉が積み上がっていた → 外へ傾けた

さらに、同じ区画に収まった玉を等間隔（0.26 区画ずつ）で並べ直していたせいで、
4 個目以降が**隣の区画に描かれていた**。並べ直すこと自体をやめて、
**止まった場所のままロータに固定する**ように直した。
これで「決まった瞬間に玉が跳ぶ」も同時に消えた（1 玉のときも跳んでいた）。
覚えるのは `(角度差, 半径, 高さ)` の 3 つだけで、角度差は区画を決めたときと同じ値なので、
描く場所が発表と違う区画に入ることが**原理的に起きない**。

減衰を**強くすると悪化した**（ポケットへ届く前に半径方向の動きが止まる）。弱いまま残してある。

### 測った

1000 回ずつ（画面を使わず、同じ `step()` を最後まで回す）。

| 玉 | 詰まり | 打ち切り | 中央秒 | 最長秒 | χ²（自由度 36・95% 上限 51.0） |
|---|---|---|---|---|---|
| 1 | 0 | 0 | 10.42 | 13.19 | 34.0 |
| 3 | 0 | 0 | 10.85 | 15.66 | 31.9 |
| 6 | 0 | 1 | 11.38 | 18.00 | 37.5 |

同じ区画に 2 個以上入った回数は、玉 3 個で 8.1%（互いに無関係なら 8.0%）。
玉 6 個は 1000 回では 32.5%（同 34.8%）で、2.3 ポイントの不足は標準誤差 1.5 ポイントに
埋もれていて何も言えなかった。**6000 回まで伸ばすと 32.4% / 標準誤差 0.6 ポイント**になり、
不足は 3.9σ。**玉はわずかに互いを避けている**と言ってよい。
衝突を入れている以上そうなるはずのもので、消していない。
（6000 回での打ち切りは 12 回 = 0.2%、χ² は 35.5。）

1000 回で「避けている」と書きかけたが、その標本数では有意でなかった。
数字の差が見えたら、まず標準誤差と比べる。

## 仰角を変えるとき

`ELEV` の 1 行だけ。画面の高さは仰角から幾何で出しているので、
傾けても枠に合わせ直す必要はない。

```js
const ELEV = 56 * Math.PI/180;   // 90°＝真上
```

## 検算

- 出目の一様性 χ² = 37.4 / 自由度 36（95% 上限 50.998）
- 賭け 156 箇所すべてが自分の座標で選ばれる
- **玉を描かずに描き直し、玉が乗っている区画の画素を読んで、そこに塗られている色と
  発表された数字の色が一致することを、玉 1・3・6 個で計 120 玉ぶん確認**（吹き出しの表示もあわせて照合）
- 盤に塗られた 37 区画の色が、5 通りのロータ角すべてで番号の並びと一致（185 点）
- 収まった玉の描画位置が、どのロータ角でも必ず発表と同じ区画に入る
- 決まった瞬間に玉が跳ばない（画面上の移動量がフレーム間で連続）
- 実プレイ 150 回で、残高が独立した台帳と 1 円もずれない
- 6 解像度で横のはみ出し無し
